## 7. Friend.tech Rise and Fall

### Timeline
| Date | Event | Metric |
|------|-------|--------|
| **Aug 2023** | Launch on Base | Invite-only, immediate viral growth |
| **Sep 2023** | Peak hype | $50M+ TVL, 250K+ users, $200K+ daily fees |
| **Oct 2023** | First decline | Volume drops 60%, whales exit |
| **Dec 2023** | V2 announcement | Brief revival of interest |
| **May 2024** | V2 launch + FRIEND token | Token launched at $3B+ FDV, quickly crashed |
| **Sep 2024** | Founder departure | Racer (founder) handed ownership to community, effectively abandoned |
| **Q1 2025** | Near-dead | <$1M TVL, minimal activity |

### Mechanics
- Users buy "keys" (shares) of other users on a bonding curve
- Key price = `(supply)² * base_price` — exponential growth
- Holding someone's key grants access to their private chat
- 10% fee per trade: 5% to key subject (creator), 5% to protocol

### Why It Failed
1. **Unsustainable ponzi dynamics**: Early buyers profit, late buyers lose — classic greater fool
2. **No real utility**: Private chats weren't compelling enough to justify key prices
3. **Whale manipulation**: Whales pumped their own keys, then sold at the top
4. **No product moat**: Social features were minimal (basic chat)
5. **Token launch killed it**: FRIEND token at $3B FDV with no utility was the final blow
6. **Founder abandoned**: Racer moved on, leaving no leadership

### Lessons
- Social tokens need genuine social utility (not just speculation)
- Bonding curves create exciting early dynamics but unsustainable long-term
- The "key = access" model needs more compelling access (exclusive alpha, tooling, community)

## 8. Fully On-Chain Gaming

### What It Means
- **ALL game logic** lives on-chain as smart contracts (not just assets/NFTs)
- Game state is public and verifiable
- Anyone can build mods, clients, or extensions (fully composable)
- Games become "autonomous worlds" — persist forever, ungovernable

### Key Frameworks
| Framework | Chain | Key Games | Developer |
|-----------|-------|-----------|-----------|
| **MUD** | OP Stack / any EVM | OPCraft, Sky Strife, Primodium | Lattice (0xPARC) |
| **Dojo** | StarkNet | Realms, Loot Survivor, Eternum | Cartridge |
| **World Engine** | Custom | Argus, Cardinal | Argus Labs |

### Notable Fully On-Chain Games
| Game | Description | Chain | Status |
|------|------------|-------|--------|
| **Dark Forest** | ZK strategy (hidden information via ZK proofs) | Gnosis | Playable (community-maintained) |
| **Sky Strife** | Real-time strategy | Redstone (OP Stack) | Live |
| **Primodium** | Base-building strategy | OP Stack | Live |
| **Loot Survivor** | Roguelike dungeon crawler | StarkNet | Live |
| **Eternum** | Grand strategy (Settlers of Catan-like) | StarkNet | In development |
| **OPCraft** | Minecraft-like (voxel world) | OP Stack | Demo (proof of concept) |

### Why It Matters
- **Composability**: Anyone can build on top of game state (mods, clients, autonomous agents)
- **Permanence**: Games don't shut down when the company does
- **Fairness**: All rules are transparent and verifiable
- **New game types**: ZK enables hidden information in fully verifiable games (Dark Forest pioneered this)

### Challenges
- **Performance**: On-chain computation is slow and expensive (limits game complexity)
- **UX**: Gas fees, wallet interactions, block times create friction
- **Storage**: Storing full game state on-chain is expensive
- **Solutions**: App-specific L2s/L3s (Redstone), session keys, gasless transactions
